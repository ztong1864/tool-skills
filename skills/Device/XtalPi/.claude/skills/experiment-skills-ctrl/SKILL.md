# experiment-skills-ctrl

## 目标

把化学实验从用户输入到方案和设备提交的流程串起来，并且只在需要确认的节点停下。

## 流程控制原则

0. 运行时以本文件为准，必要时重新读取本文件和参考说明以恢复流程规则。
1. `constraint-parser` 生成的约束 JSON 只作为内部流转数据，不展示给用户。
2. 需要停下确认的时机是：候选推荐后、化学品用量后、实验步骤后、实验方案文件后、任务提交前。
3. 下游 skill 失败时立即停止并返回错误，不继续后续步骤。
4. 下游 skill 失败时要先提醒用户问题出在哪一步，等用户反馈后再重试。
5. 未获用户明确确认前，不得提交设备任务。
6. `fdu-device-run` 只有在用户明确确认后才能调用；只有用户明确要求时才启用 `--enable-start`。

## 方案生成链路

当用户提供实验目标或约束条件时，按以下顺序执行：

1. 调用 `constraint-parser` 解析约束条件。
2. 调用 `literature-experiment-recommender` 生成 ATA 推荐实验条件。
3. 在候选推荐后停下，向用户展示推荐表格，确认推荐的组合。
4. 调用 `chemical-amount-calculator` 计算所需化学品用量。
5. 在化学品用量后停下，向用户展示实际投料表，确认每个试剂、底物、溶剂和添加剂的用量换算是否正确。
6. 调用 `experiment-step-generator` 生成实验步骤。
7. 在实验步骤后停下，向用户展示编号步骤列表，确认步骤顺序、反应时间、温度和后处理步骤是否正确。
8. 调用 `fdu-experiment-plan` 生成实验方案文件。
9. 在实验方案文件后停下，向用户展示方案文件路径和方案摘要，确认生成的实验方案内容是否正确。

## 方案执行链路

当用户提供实验目标或方案文件，并且需要生成设备协议时，按以下顺序执行：

1. 调用 `fdu-multi-step-json` 生成总 step JSON。
2. 调用 `fdu-resource-verify` 对 step JSON 做资源校验。
3. 调用 `fdu-unit-orchestration-json` 生成设备协议。
4. 在任务提交前，向用户展示准备提交的任务摘要、协议对应的方案信息和提交目标。
5. 用户确认后再调用 `fdu-device-run` 提交任务。

## 用户引导流程

### 情况一：用户只说“开始化学实验”

如果用户只输入“开始化学实验”而没有给出详细信息，就按下面的节奏推进：

1. 先提示用户输入化学反应空间信息。
2. 用户输入后，自动进入约束解析。
3. 继续自动进入候选推荐。
4. 候选推荐完成后停下来，展示推荐表格并确认。
5. 用户确认后继续化学品用量计算。
6. 化学品用量计算完成后停下来，展示用量表并确认。
7. 用户确认后继续实验步骤生成。
8. 实验步骤生成完成后停下来，展示步骤列表并确认。
9. 用户确认后继续实验方案文件生成。
10. 实验方案文件生成后停下来，展示方案文件摘要并确认。
11. 用户确认后继续机器协议生成。
12. 协议生成完成后，进入任务提交前确认，展示待提交任务摘要。
13. 用户确认后才提交任务。

### 情况二：用户直接要求“生成协议”或“执行实验”

如果用户已经提供完整化学反应空间信息，并直接要求生成协议或执行实验，就按下面的节奏推进：

1. 直接执行方案生成链路和方案执行链路中需要的步骤。
2. 在候选推荐、化学品用量、实验步骤、实验方案文件节点停下，并分别展示对应内容给用户确认。
3. 在任务提交前再停一次，展示待提交任务摘要给用户确认。
4. 用户确认后提交任务。

## 注意事项

- 不得编造资源、协议或设备执行结果。
- 方案生成链路中，除了候选推荐后、化学品用量后、实验步骤后、实验方案文件后、任务提交前这 5 个时机，其他节点没有问题就默认继续流程。
- 任务提交前必须明确确认。
