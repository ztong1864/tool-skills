# Oasis Lab Environment Rules

本文档描述绿洲实验平台的物理结构、系统语义和执行边界。  
它用于指导 Agent 在创建实验、推进 workflow、分配库位和启动实验时，正确理解平台行为。

## 1. 平台物理结构

绿洲实验平台可以理解为两大区域：

- 小分子药库
- 实验台

平台上存在两个机械臂，负责在不同位置之间移动物料。  
药库和实验台之间还存在机器人小车，用于在两个区域之间传递物料。

从 Agent 的视角看，平台中的很多步骤本质上都是：

- 机械臂搬运
- 小车传递
- 设备执行协议

## 2. locationId 的含义

绿洲系统中的 `locationId` 表示平台上的一个物理位置。  
它不是药物名称，不是样品名称，也不是 workflow 步骤本身，而是“某个物料被放置或可被放置的位置”。

Agent 在执行入库相关操作时，应这样理解：

- 分配库位，本质上是在分配位置
- 入库，本质上是在把某个对象登记到某个位置
- 这不等于真实世界里已经自动放好了物料

因此，Agent 不应把“库位已分配”误解为“物料已经由系统自动准备完成”。

## 3. 调度-等待 的含义

在 workflow 中，`调度-等待` 通常表示平台的运输、调度或等待过程。  
它常常对应：

- 机械臂搬运
- 小车传递
- 设备间的流程衔接等待

因此，Agent 在阅读 workflow 时，应把 `调度-等待` 视为平台调度动作，而不是实验处理本身。

## 4. 创建实验流程的真实含义

在绿洲系统中，新建实验流程本质上不是“立即执行一次实验”，而是“定义一组后续可执行的设备动作”。

这些动作通常包括：

- 机械臂动作
- 小车传递动作
- 移液站动作
- 高内涵成像仪动作

这些动作通过 workflow 中的 step 和 protocol 进行配置。

因此，Agent 在新建实验时应这样理解：

- 新建实验流程，主要是在组织动作链
- workflow 决定流程结构
- protocol 决定具体设备如何执行某一步

## 5. 物料信息对新建实验的影响

创建实验流程时，是否已经完整提供物料信息，通常不影响流程本身的创建。  
原因是系统首先创建的是动作链，而不是立即验证现实中的每一个物料是否已经摆放完毕。

因此，Agent 应注意：

- 不要因为当前还没有完整物料信息，就误以为无法创建实验流程
- 新建实验流程与后续物料放置，是两个不同阶段

这意味着在很多场景下，Agent 可以先完成：

- workflow 选择
- step 参数配置
- protocol 配置
- 实验流程创建

然后再进入物料准备和位置分配阶段。

## 6. 启动实验 的真实含义

当前 `oasis-start` 的含义，不是“实验已经立刻在现实中自动开始执行”，而是：

- 把已经创建好的实验流程上传到系统实验队列

真正的现实执行仍然需要人工确认。  
操作员会在系统界面中完成最终确认，并在需要时手动放置物料。

因此，Agent 应这样理解 `start`：

- `start` 是提交到队列
- 不是最终现实执行确认
- 提交后仍然存在人工审核和人工启动环节

## 7. Agent 的默认行为规则

在绿洲任务中，Agent 应默认遵循下面的判断规则：

### 7.1 关于 workflow

- 先关注 workflow 是否正确表达实验思路
- 再关注 step 和 protocol 是否匹配
- 不要先被“物料是否已经实际摆放”阻塞

### 7.2 关于入库

- 把入库理解为“位置分配与系统登记”
- 不要把入库理解为“系统已经自动把真实物料放到位”

### 7.3 关于 start

- 把 start 理解为“加入实验等待队列”，真的启动还需要人工点击确认
- 不要把 start 理解为“现实执行已经不可逆地立即开始”

### 7.4 关于人工操作员

现实中通常是：

- 操作员向 Agent 描述实验思路
- Agent 选择、整理或改写合适的 workflow
- Agent 创建实验流程并推进到合适阶段
- 操作员手动放置物料
- 操作员在系统界面中确认真正启动实验

因此，Agent 的重点应放在：

- 理解实验意图
- 选择正确 workflow
- 配置正确 step 和 protocol
- 按流程推进系统状态

而不是过早担心现实物料是否已全部放置完成。

## 8. 一句话总结

绿洲平台首先是一个“设备动作编排系统”，不是一个“自动理解全部现实实验上下文的全自动实验员”。  
Agent 的工作重点是正确创建和推进流程，把实验送入可执行状态；现实物料放置和最终执行确认，仍然依赖人工操作员。
